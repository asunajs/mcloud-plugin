# mcloud-plugin

把 [mcloud](https://github.com/asunajs/mcloud)（中国移动云盘的 Rust 自动化服务）**用 JS/TS 重写一份**，
作为 [rust-plugin-panel](https://github.com/asunajs/panel) 的插件跑起来。

两个目标**同等重要**：

1. **功能**：mcloud 的任务与界面在插件形态下真的能用
2. **压力与优化**：它是这个面板能碰到的最大的东西 —— 用它把面板的边界压出来，
   每压出一个就回面板仓库修掉，并在 [`docs/findings.md`](docs/findings.md) 记下
   「怎么测的、什么数、改了什么」

## 它长什么样

**四条插件、三条任务、一个界面。**

| 插件 | 是什么 |
|---|---|
| `mcloud` | 界面 + 所有路由（读数 / 登录 / 配置）。**没有定时任务。** |
| `mcloud-daily` | **日常** —— 一次触发从头跑到尾 |
| `mcloud-exchange` | **兑换** |
| `mcloud-live` | **直播** |

界面是**菜单栏 + 一次一块**，六块：账号 / 日常 / 兑换 / 直播 / 数据 / 推送。
每块第一行回答那个块的核心问题（「登录了吗」「今天跑了吗」「口令池里有几条能用」），
**读数直接显示**，按钮说人话（「现在跑一次」「贴进去领取」「扫码登录」）。

⚠ 界面上**没有「设置」页**（原来那一页是六个地址口子 + 自检）。那些口子是
**搭测试环境**用的，用户看不懂、还会把面板指到错的地方去。要改基址请直接调
`/plugins/mcloud/api/config`（`scripts/e2e-mock.sh` 就是这么做的）。

截图在 [`docs/shots/`](docs/shots/README.md)。

> **这一版推翻重做过一次。** 前一版是「25 条一次一步的任务 + 七张卡片平铺 +
> 一个『高级』开关 + 二十几个按钮」，用户的原话是
> **「界面完全搞不懂，文字一大堆，按钮点哪个都不知道」**。
> 改的过程、以及每一步的理由写在 [`docs/redesign-plan.md`](docs/redesign-plan.md)。

## 三个设计决定（其余都是它们的推论）

### ① 任务是**一次跑完**的，不是"一次一步"

前一版把每条流程拆成"一次调用一个请求"的状态机。那是被**面板的 2 秒执行预算**
逼出来的：预算打断不了正在阻塞的 `http_fetch`，所以只能保证"每次调用足够短"。

用户说得很清楚：**2 秒不是他的需求**。所以解法换成两条面板侧的能力
（见下「面板为此补了什么」）：

- **长任务隔离 + 粗粒度共享**：抢兑与路由插件 `worker_hint('exclusive')`；
  日常/直播共享一条粗粒度 lane，面板自动抬到 4 条线程
- **按任务声明执行预算**：`register_cron(name, expr, handler, { budget_ms })`

有了这两条，「日常」就能是一条**从换票一路跑到快照**的函数（15 步、几十个请求），
而不是 25 条任务互相接力。

### ② 登录**恰恰必须**一步一步 —— 因为状态机是用户本人

```
扫码：我出码 → 用户掏出手机扫 → 用户在手机上点确认 → 我才拿到凭据
短信：我发码 → 用户看手机 → 用户把 6 位码告诉我 → 我才拿到凭据
账密：用户给我手机号和口令 → 我一次换到凭据
```

中间那几步的**时间由用户决定**。硬塞进一个"从头跑到尾"的函数，结果只能是
"函数停在等用户输入"。所以：**登录走路由、触发者是用户点按钮；任务一次跑完。**
账密没有用户交互，所以它**一个路由就完成**。

### ③ 查询是**读数**，不是任务

面板的日志是**环形 200 行**、混着所有插件。所以：

- 读数走**一个**聚合接口 `GET /plugins/mcloud/api/readings`，一次给全七个区块
  （前一版是一个区块一个接口 ⇒ 每块各有各的加载/错误状态 ⇒ 没人知道该看哪个）
- 「一次运行」的结果**落一条读数**（日常把整趟的每一步结果存下来），界面读它
- 这个接口**只读**：一个上游请求都不发 ⇒ 打开页面永远不会因为上游慢而卡住

## 先跑起来（不用真账号）

```bash
# ① 一整套本地验证：类型、测试、产物一致性、拆分检查
npm ci && npm run all

# ② 对着 mock 上游跑完整条链 —— **绝不碰真账号**，也不需要你的凭据
./scripts/e2e-mock.sh <面板可执行文件> 18900
```

`e2e-mock.sh` 会起 mock 上游 + 一个面板实例，把上游指向 mock、导入一份假会话，
然后**三条任务各跑一次**，断言协议层逐字节正确：签到三段式（含回查）、
领小红花六步链 11 个请求、H5 换票四步含 smid、WS 升级头、query 逐字节 ——
以及 **mock 侧的状态真的变了**（`todaySigned` / `curMonthBackupSignAccept` / 领取清单 / 通知）。

它和你跑的是**同一份脚本**，CI 里跑的也是这一份。

## 装到你自己的面板上

```bash
# 面板的插件目录指向本仓库的 plugins/（一个静态二进制 + 一个目录，没有依赖）
#
# ⚠ 新一点的面板**默认不认明文令牌**（`PANEL_TOKEN=<明文>` 会直接退出）。
#   要么用摘要形态（推荐，口令不离开浏览器）：
PANEL_TOKEN_HASH="$(printf '%s' '<你的令牌>' | <面板二进制> hash-token)" \
  PLUGINS_DIR=/path/to/mcloud-plugin/plugins <面板二进制>
#   要么本机临时开一次开发口子：
# PANEL_ALLOW_PLAIN_TOKEN=1 PANEL_TOKEN=<你的令牌> PLUGINS_DIR=… <面板二进制>
#
# ⚠ 直播那条链要面板能谈 CBC 套件（上游只给 CBC，rustls 不实现任何一个）。
#   面板从 2026-10-17 起**默认就编进去了**（`default = ["legacy-tls"]`），
#   所以直接 `cargo build --release` 出来的二进制就能直播 —— 不用加参数。
#   自己精简过（`--no-default-features`）才需要补回来；「自检」有一条
#   「宿主支持 native TLS」替你盯着，红了就是编漏了。
```

登录页面会把口令先在浏览器里算成 `sha256("plugin-panel/v1:"+口令)` 再提交；
走接口的话，`{"token": "<那个摘要>"}`。

装好后：

* 面板侧边栏出现**「云盘」**入口，点进去就是七块界面
* 面板的任务列表里出现**两条**任务：日常 / 直播；**兑换不占面板任务列表** ——
  它是兑换功能的一部分，配置在「云盘 → 兑换 → 定时抢兑」里。一条计划 = 一个账号 +
  一个目标（`prizeId`）+ 一个整点；两个号换不同的东西/不同的时间就建两条计划。
  面板仍只有一条「兑换」任务，cron 取所有启用计划整点的**并集**（如 `0 10,20 * * *`），
  到点由插件按目标整点分发（面板只负责叫醒和记录）
* 日常默认**每天 8:00 / 20:00**（第二趟是兜底，不是重复扣次数）
* 想让它立刻干活：界面上点「现在跑一次」，或者
  `curl -X POST -H 'X-Panel-Token: <令牌>' -H 'x-panel: 1' '<面板>/api/tasks/mcloud-daily/%E6%97%A5%E5%B8%B8/run'`

> ⚠️ 写接口（POST）必须带 `-H 'x-panel: 1'` —— 面板的防跨站请求伪造要求，
> **插件自己注册的路由同样适用**（见 [`docs/findings.md`](docs/findings.md) F-007）。

## 面板为此补了什么

插件这一版能成立，靠的是面板侧**六项新能力**（都在 `rust-plugin-panel` 里，已合入）：

| # | 能力 | 为什么这个插件非要 |
|---|---|---|
| ①-1 | **worker 隔离**（`worker_hint('exclusive')`） | 抢兑和长路由不能被 15 步的日常/直播拖住；日常/直播共享粗粒度 lane |
| ①-2 | **任务参数**（`register_cron(..., { params })`） | 脚本任务用；兑换的多计划走插件自己的计划表（一条计划一个账号），面板仍是一条任务 |
| ①-3 | **侧边栏入口**（`register_nav`） | 插件得在面板上有个门 |
| ①-4 | **随机表达式**（`@every 5s -200ms` / cron 抖动） | 定时不该齐步走 |
| ①-5 | **`smtp_send`** | 10 个推送渠道里，邮件是唯一要发信的那条 |
| ①-6 | **按任务/路由声明执行预算**（`{ budget_ms }`） | **没有它三条任务一条都跑不起来** |

①-6 是那条"没有它整件事不成立"的：一个从头跑到尾的函数**必然**超过默认的 2 秒。

## 仓库结构

```
mcloud-plugin/
  src/                     TS 源码
    crypto/                纯 JS 密码学（md5/sha1/sha256/hmac/aes/**二维码**）
    mcloud/                上游层：签名、信封、H5、登录、会话、口令池、直播…
      tasks/               每条任务的协议逻辑
    entries/               四个插件入口（mcloud / daily / exchange / live）
  plugins/js/*.js          构建产物（单文件，提交进仓库，CI 检查是否最新）
  plugins/mcloud/          WebUI 静态文件（原生 ESM + CSS，零依赖）
  mock/upstream.mjs        mock 上游（CI 全程只打它）
  scripts/                 构建、e2e、拆分检查、截图
  docs/                    见下
```

## 起名即分组

面板把插件按**名字里第一个 `-` / `_` 之前那段**归拢显示（`mcloud-*` 一组、
`bilibili-*` 一组），每组带「全部重载 / 全部启用」。

所以四个插件**前缀都用 `mcloud`** —— 面板上它们聚成一块，而不是散成一排。

## 零运行时依赖

QuickJS 沙箱里没有 Node（没有 `fs` / `net` / `crypto` / npm 包），
`host-api` 由面板的 Resolver 提供。所以：

- 密码学、UTF-8、hex、base64、PNG 解码、二维码**全部自己写**
  （沙箱里连 `TextEncoder` / `Buffer` 都没有）
- 产物是**单文件**、零依赖；界面是原生 ESM + CSS，零构建

## 安全

- **上游账号不是测试资源**：CI 全程只打 mock；真账号只在本地手工验，且**优先只读任务**
- **凭据不进日志、不进读数、不进界面**：要给界面看的一律走 `maskAuth` / `maskPhone`
- 兑换会**花真 AI豆**（上游无幂等键）⇒ 界面上的「现在试一次」是显式动作，不自动跑
- 登录的**口令**先按协议哈希再发出去（`SHA1("fetion.com.cn:" + 口令)`，大写 hex），
  不上传明文；日志与错误信息里都不回显口令
