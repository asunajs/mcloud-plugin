# 真机验收（⑤-5）

这一步**只能在你的真机上做** —— 它要打真上游、要扫真码、要花真豆。
下面把它拆成「照着点」的步骤，每步都写清**看什么算过**、**不过要回报什么**。

> 本地能验的都已经验过了（`npm test` 712 项 · `split_check.py` 105 项 ·
> `e2e-mock.sh` 18 项 · 9 张截图）。这一份是**剩下那一半**。

## 1 · 登录（扫码）

界面 → **账号** → 「扫码登录」。

**看什么算过**：

1. 二维码**真的显示出来**（不是空白框）—— 早期版本这里是空的（`svg` 只在
   `/login/qr/start` 返回，而界面只调 `/readings`）
2. 手机 App 扫 → 手机上点确认 → 界面**自己**变成「已登录 138xxxxxxxx」
3. 「账号」区块出现一条账号，可以切换/删除

**不过要回报什么**：卡在第几步、界面上的原话、以及面板日志里 `[mcloud]` 那几行。

---

## 2 · 登录（另外两种）

同一个「账号」区块里还有 **短信** 与 **账密**。

**看什么算过**：

- **短信**：填手机号 → 发码 → 填码 → 有时会出现滑块（拖一下）→ 登录成功
- **账密**：填手机号 + 密码 → **一个请求就完事**（不是"推进一步"那种状态机）

**注意**：短信滑块那一步是**唯一**该出现"分步"的地方 —— 因为等的是**你**。
账密不该有分步。

---

## 3 · 日常（真跑一次）

界面 → **日常** → 「现在跑一次」。

**看什么算过**：

1. 下面「最近几次」多出一条，**默认展开**
2. 展开后是**一串步骤**（不是一行 JSON）：每一步一行，名字 + 结果
3. 有任何一步失败，那一步是**红的**，且失败原因写的是人话
4. 面板日志里 `[mcloud-daily]` 有**一次**运行的记录（不是 25 条）

**⚠ 重点看**：结果对不对 —— 签到/领取那几步有没有真的生效（去 App 里核一下）。

**不过要回报什么**：那张步骤列表的原话（截图最好）。

---

## 4 · 兑换（**干跑**，不花豆）

界面 → **兑换** → 先填「要换什么」（比如 `1元话费`）→ 「现在试一次」。

**看什么算过**：

1. 顶部那行显示「离这一场还有 X · 每天 10 点 · 压整点前 10ms 发」
2. 点「现在试一次」之后，结果里**明确有一句「一枪都没发」**
3. 「奖品清单」出现真实奖品与余量
4. 面板日志里**没有** `exchangeV3` 这一条请求

**⚠ 这一步是安全的** —— 干跑只读清单、查余额、预热、取题解滑块，
到"只差下单"就停。真下单只走定时那一场。

**不过要回报什么**：那句「一枪都没发」在不在、清单有没有出来。

---

## 5 · 兑换（**真抢**，会花豆 —— 想清楚了再做）

1. 「每天几点」填一个**最近**的整点（比如现在是 14:20，就填 `15`）
2. 到点前 1 分钟盯着「兑换」页
3. 到 `hh:59:40` 那行字应该变成「正在抢兑窗口里」
4. 整点过后「最近几次」多一条，里面能看到：
   - `压整点前 10ms 发`
   - 每个账号的 `离第一枪 +Nms`（多账号时）

**看什么算过**：豆真的少了 / 奖品真的到了，且**只发了一枪**。

**⚠ 不过要回报什么**（这一条最要紧）：

| 现象 | 说明什么 |
|---|---|
| 抢到了 | 一切正常 |
| 没抢到，但只发了一枪 | 正常的抢兑失败（手速/网络），不是 bug |
| **发了两枪以上** | **小时闸失效** —— 这是最严重的，立刻回报 |
| 界面停在「正在抢兑窗口里」很久 | 自旋卡住 —— 回报面板日志与当时时刻 |

**看什么算过**：四态结论（`200108` / `200112` / `200118` / 未分类）各自对应
人话，而不是错误码。

## 7 · 推送

界面 → **推送** → 配一个渠道（比如 PushPlus）→ 「试一下」。

**看什么算过**：

1. 配过之后显示「已配」，没配的显示「填」
2. 「试一下」真的收到消息
3. **密钥不回显** —— 显示的是 `abc…yz（共 N 字符）` 这种
4. 跑完一次「日常」之后，收到一条**汇总**（一次运行一条，不是每步一条）

**看什么算过**：所有口子**平铺**在这里，**没有「高级」开关**，
也没有任何"藏起来"的东西。
