# CLI 默认每日任务 vs mcloud-sign：差异清单

日期：2026-10-23
范围：**无参数默认入口**（每日任务），不含直播导出。
基准：参考实现 `/Users/catlair/mobile/workspace/mcloud-sign`（2.1.0，`packages/cli/src/index.ts`）。
本仓：commit `883b139` + 当前未提交改动。

## 先定判据：对齐的是**用户看得见的东西**

这份清单里的每一条"差异"，判据都是用户在屏幕上/推送里/账号上看到的：

- 日志里出现哪些行、每行怎么说；
- 一个账号/一趟任务最后算成还是没成；
- 推送正文里有什么；
- CLI 的退出码；
- 账号上的数据（云朵/AI豆、文件、奖品）变成什么样了。

**不是**对齐参考实现的内部写法。实现细节（拆几个函数、用哪个状态键、发哪几枚头、
甚至调哪个端点）可以不同 —— 否则重写就没有意义。
所以"参考实现也是这么做的"**不能**当作保留一个用户可见差异的理由；
反过来，它也不能当作"照抄旧端点"的理由：端点有新旧之分，认的是当前客户端在打的那一支。

鉴权与端点的实测读数（哪些接口认 `jwttoken`、哪些认 `Authorization`、
「今日云朵」为什么从旧 `cloudRecord` 换成 `cloudRecordV2`）记在
[`auth-families.md`](auth-families.md)。

## 0. 先说结论

默认入口两边都是每日任务，这一点一致。不一致在后面三层：

1. **任务集**：参考实现的每日入口包含 AI 头像、春日拍拍、AI 抽奖、云朵大作战等条件任务；本仓的日常没有这些实现（有些在 `groups.ts` 里明确标了 `implemented: false`）。红包派对已在 2026-10-23 接进日常（第 ④.5 步），直播口令仍只在默认日常之外提供导出。
2. **日志形状**：已对齐——CLI 现在也是 `[info] HH:MM:SS` + 账号段头 + 账号完成行，不再每行带 `[账号]` 前缀；颜色由 `common.colorize` 控制。面板日志没有跟着改（仍走 `host-api` / `userLine`）。日常尾部已补「今日云朵」与「清理临时文件」，两边共用同一条 `runDaily`，所以面板日志和运行结束推送也会带上这两行。
3. **换票与退出码**：两边的换票都已走通（参考实现的旧地址已在 2026-10-23 换到新地址）；退出码仍不同：参考实现单账号任务失败仍退出 0，本仓会退出 1。

## 4. 日志形状

参考实现（源码可确认的格式）：

```text
[info] 11:04:00 配置文件: ...
[info] 11:04:00 共 1 个账号
[debug] 11:04:00 [account] === 账号 1 开始 ===
[info] 11:04:00 ------ 账号 1 (账号1) ------
[info] 11:04:xx 网盘签到成功
[info] 11:04:xx 账号 1 执行完成
[info] 11:04:xx 全部执行完成
```

本仓真实运行（见 §1）：

```text
[info] 11:27:33 ------ 账号 1 (账号1) ------
[success] 11:27:33 签到：网盘签到成功，获得 3 云朵
...
[info] 11:27:33 账号 1 执行完成
[info] 11:27:33 全部执行完成
```

已对齐：时间/级别、账号段头（带序号与 label）、账号完成行、去掉每行 `[账号]` 前缀、`common.colorize` 控制颜色。
仍未对齐：

- 没有 banner / 设备信息 / 登录过期时间；
- 任务原话仍带任务名前缀（`签到：网盘签到成功，获得 3 云朵`），参考实现那几行常是 `网盘签到成功`；
- 非 TTY 或 `colorize:false` 时没有颜色（这是有意的，日志落盘时不该带 ANSI）。

## 5. 不能照搬的部分

1. **旧换票路径**：参考实现原来打 `caiyun.feixin.10086.cn/portal/auth/v2/tyrzLogin.action`，真账号回 404；2026-10-23 已换成 `m.mcloud.139.com/ycloud/auth-service/auth/tyrzLogin`，别再回退。本仓走 H5 三段换票，两边现在都能跑通。
2. **任务失败仍退出 0**：参考实现的账号内 catch 是历史行为，不适合当成 CLI 契约；本仓退出 1 更利于 cron/CI 判断。
3. **JS/MJS 自动写回**：参考实现会把配置转换成 JSON、把旧 auth 写回文件；本仓目前只读不改。要不要写回是产品决策，不是单纯的对齐。
4. **旧推送配置**：本仓有完整的 `src/mcloud/push.ts`，但 standalone 没接线；`docs/standalone.md:103` 却写着“HTTP 推送渠道可用”。要么接线，要么改文档，别维持现状。

## 6. 建议的处理顺序

1. **先定任务集范围**：默认日常要不要补参考实现的条件任务（AI 头像 / 春日拍拍 / AI 抽奖 / 云朵大作战 / 直播口令）。其中 AI 头像、AI 抽奖、春日拍拍在 `groups.ts` 已标未实装或上游证据不足，不能按"缺了就补"处理。红包派对不在此列——它已在 2026-10-23 接进日常，缺的是**第一次真跑的读数**，不是实现。
2. **日志形状已对齐（2026-10-23）**：CLI 换成参考实现的 `[级别] 时间` 形式，去掉每行 `[账号]` 前缀，补账号完成行；面板侧未改。剩余 banner / 设备信息 / 登录过期时间 / 任务原话前缀，等任务集定下来再一起看。
3. **补推送或改文档**：`message` 目前是静默丢弃，必须二选一。
4. **定退出码契约**：单账号任务失败到底该不该让整个 CLI 退出非 0，写成明确规则并加一条测试。

日志形状已按本清单落地（只动 CLI 表现层）；任务集、推送、退出码尚未动。
