# 界面用词（给用户看的话）

> 用户不懂实现。**任何出现在界面上的字**都按这份表写。
>
> 这一份是从「用户只看三件事 + 一个『高级』角」那一版留下来的，**规则改过一次**：
> 现在没有「高级」角了（藏东西反而让人怀疑有更重要的没显示），
> 所以原来写着"只在高级里出现"的那些词，现在的判据变成 **「它是不是用户要读的字」**。

## 一句话规则

**界面只说"你要做什么、成了没有"。** 怎么做到的、打到哪个地址、动了哪张表 —— 不写。

## 对照表

| 不要写 | 要写 |
|---|---|
| 上游 / 上游地址 / 真上游 | **移动云盘**（「来自移动云盘」/「地址」） |
| mock / 本地 mock | **不出现**。这是开发期的东西，用户界面里没有它的位置 |
| docs/xxx.md、ISO 时间戳、`state` 表、句柄、PROVISION、member/apply | **一律不出现**；换成「还没登录，先贴凭据」这类人话 |
| 任务名（`live-listen` / `session-refresh` / `exchange-list`…） | **不出现**。界面上是「日常」「直播」「兑换」，不是任务名 |
| 风险标签（记账 / 不可逆） | **不出现**。真需要提醒的写成一句中性的话（见下） |
| 内部动作名（「只验证」「换票」「推进一步」「算一次」「现在探一次」） | 用户的事：「现在跑一次」「贴进去领取」「扫码登录」 |
| **「会写进你的账号」/「会真往账号里写」/「确定现在领？」** | **一句都不要** —— 用户点「领奖励」是理所当然的事，配这种雷像"点了可能出事" |
| 弹窗确认（「现在做？」） | **不弹**；一键就是一键。真需要说明的写在那一块里（中性一句） |
| 「表达式」「cron」「budget_ms」 | 不出现。「每天 7:00–22:00 每 30 分钟」 |

## 什么该出现在哪一块

七块各自第一行回答一个问题 —— 那**就是**这一块允许出现的字：

| 区块 | 第一行回答 | 里面可以有 |
|---|---|---|
| 账号 | 登录了吗 | 账号列表、设备号、三种登录方式、贴会话串 |
| 日常 | 今天跑了吗 | **最近一次运行的每一步**（这是唯一允许出现步骤名的地方 —— 而步骤名是人话，如「签到」「领 AI 豆」） |
| 兑换 | 要换什么 · 换得到吗 | 兑换目标、奖品清单 |
| 直播 | 口令池里有几条能用 | 口令、下一场几点、听窗口状态 |
| 数据 | 读了几个市场 | 纯读数，**没有任何动作** |
| 推送 | 还没做（阶段 ⑤） | —— |
| 设置 | 所有口子平铺在这里 | 五个上游地址、听窗口参数、自检 |

## 两条容易违反的

1. **错误信息也是给用户看的字**。`HTTP 502` 不算说明；要写成
   「移动云盘没回应（502），过一会儿再试」。做不到"说清原因"的时候，
   至少要**带上原始文本**，而不是只回一个状态码。
2. **「还没做」要明说**，不许留一个点了没反应的按钮，也不许画一个看着像好的空表
   （推送那一块现在就是「还没做（阶段 ⑤）」，而不是一张空渠道表）。
