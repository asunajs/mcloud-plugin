# 直播（小红花）业务规格

这份是**业务口径**：这个功能在现实里是怎么运作的、我们据此怎么实现、哪些还没被证实。
实现细节看代码（`src/entries/live.ts`、`src/mcloud/tasks/live*.ts`、`src/mcloud/koulingPool.ts`）；
历史踩坑看 `docs/findings.md` 的 F-087 / F-088。

---

## 1. 两条路

### 1.1 手动（主路径）

- **什么时候**：用户在直播**开启期间**，把口令贴进「直播」页（一条或多条）。
- **做什么**：选中的账号（默认「全部账号」）**依次领取所有口令**。
- **不做什么**：不开门、不看小红书、不听弹幕。
- **为什么**：口令已经在手里了，开门和抓取都是白跑；而且门偶发失败会把一趟
  本来能跑完的领取拖黄（参考实现把这条写成了硬规矩：有 `codes` 就跳过开门）。

### 1.2 定时（碰运气）

- 直播的**开播时间固定**（整点档），但**开播日期不固定** —— 上游有时会给"下一场"
  的具体日期，只是有时，不能依赖。所以只能**每天去碰**：`30 10,15 * * *`（10:30 / 15:30）。
- 顺序：

  ```
  ① 收口令（整趟只跑一次，用第一个账号的凭据）
     开门（房间列表）
       ├─ 没开播 / 开播的不是「中国移动云盘」 ⇒ 到此为止（零请求）
       └─ 开播 ⇒ 看小红书 → 听弹幕
  ② 领（每个账号各领一次，用共享池里的口令）
  ```

- ⚠ **"听"只跑一次，不按账号分。** 口令是共享的：**一个账号听到，所有账号都能用**。
  按账号分着听等于 3 倍请求、3 倍时间，还会重复撞同一批弹幕。
  "按账号"只发生在**领取**那一步（因为"哪个账号领过哪条"必须分开记）。

- **口令的两个来源**（弹幕这一侧）：
  - 其他用户**进入直播间**时，系统会**以他的名义**自动发一条口令；
  - 别的用户也可能**主动分享**（常常是**另一条**）。
  - ⇒ 系统给的只有一条，另一条往往要靠别人的分享才能捡到。
- **小红书**：上面是别人从别的路径拿到的口令。**有封控**，不能频繁请求
  ⇒ 我们限制成两次之间 ≥ 30 分钟（`XHS_MIN_INTERVAL_MS`）。

## 2. 口令与共享池

### 四条硬口径

1. **只记当期，不长期保存。** 池是"这一场直播"的池：周期翻篇（5 小时兜底，或
   "判定门关掉 + 10 分钟宽限"）就把口令与领取记录一起清掉。
   小红书限速、抓取间隔**不跟着清** —— 那是防封的节流，与场次无关。
   ⇒ 每个"用池"的地方都走 `loadFreshPool()`，不允许直接读原始池。
2. **判过无效的口令要记住，别再抓进来。** 池里留着它（`state: invalid`），
   收集时不再入池、投放时也不再投 —— 否则每轮白跑一枪 `200108`。
3. **够 2 条有效就停止收集。** 一场只发那么几条，继续抓只是重复撞同一批，
   而且每次抓取都在给对方风控送样本。
4. **按账号记"用掉了哪条"。** 同一个账号用过口令 A 就不再投 A；
   但**别的账号还能用 A** —— 口令是共享资源，账号不是。

### 事实与做法

| 事实 | 我们的做法 |
|---|---|
| 口令**只在直播开启期间**可用 | 池按"当期"管（见口径 1） |
| 一场（当期）通常 **2 条**，偶尔 3 条 | 池按场收，不设上限 2；阈值只用于"停止收集" |
| 这 1~3 条**所有账号都能用** | 池共享；`claims` 是 `账号 → 口令 → 结论` |
| 某个账号领过某条 | 记在 `claims`，挑口令时跳过（换号照旧能领） |

判据落在 `planDrawCodes(pool, account, humanCodes)`：人给的在先、池里该投的在后；
**已判无效**的不投，**这个账号领过的**也不投。

## 3. 领取结果的分类

| 服务端 | 含义 | 我们对用户的说法 | 下一步 |
|---|---|---|---|
| `code=0` + `flowerNum` | 领到了 | 领到 N 朵 | — |
| `200112` | 这个账号**已经领过**这条 | 已领过 | 换账号，或等下一场 |
| `200108` | 口令**不存在**（抄错了） | 口令无效 | **值得重贴/重听** |
| `200118` | 口令**存在但不是当期** | 认识，但本场已经结束了 | **不是口令的问题**，别让人重抄 |
| `200110` | 首次参与已参与过 | 已参与过（正常） | — |
| 其他数字码 | 未分类 | 服务端回 N | 只记账，不猜 |

⚠ 进账数取 **结束余额 − 开始余额**，不是把各口令的 `flowerNum` 相加 ——
相加会漏掉「首次参与惊喜奖」那几朵（它不属于任何一条口令），那正是"总数对不上"的常见来源。

## 4. 领小红花需要服务端开启

界面那个开关只是**允许插件去领**；功能本身要在服务端那边开。
没开时我们如实说「领小红花没开（要先在服务端那边开启）」，不假装能领。

## 5. 验收状态（哪些有实证、哪些没有）

| 环节 | 状态 |
|---|---|
| 开播门（换 SSO → 直播侧 JWT → 房间列表） | **有实证**：跑通过"今天没直播""在播的那间不是中国移动云盘"两种结论 |
| 弹幕抓口令 | **零实拍**：真机 `wss://` 一次都没连上过（没赶上目标房间开播）。帧序、`command` 取值、UNREAD 等按原项目实现，未经实拍 |
| 小红书抓口令 | 与弹幕**同级并发**；能否真抓到未验（小红书有封控） |
| 领小红花 | 打到过"领取"那一枪，但喂的是无效口令 ⇒ 链路通、**进账 0 从未变成进账 N** |

⇒ 界面上把"自动收口令"标成未验证，并提示"稳妥的做法是自己贴"。

## 6. 三条硬边界

1. **没开播就早退** —— 零请求。没开播时抓到的口令一定是无效的，所以"先验开播"是
   判据而不是限制。
2. **门失败 ≠ 今天没直播** —— "我们凭据坏了"和"今天没开播"是两件事，前者如实上抛。
3. **贴了口令就跳过开门** —— 见 1.1。
